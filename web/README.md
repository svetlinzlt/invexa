# Invexa — целева страница

Точка **0.1 и 0.2** от плана за реализация: събиране на имейли и измерване
дали цената е вярна. Тази страница не е маркетинг — тя е измервателен уред.

Ако след четири седмици няма ≥ 300 записани и ≥ 3% избрали премиум,
[планът](../app-idea-plan-bg.md) казва да спреш или да преработиш модела,
преди да си написал приложението.

---

## Стартиране

```bash
npm install --prefix web
```

```bash
npm run dev --prefix web
```

Отваря се на <http://localhost:3000>. Формата работи чак след стъпките по-долу.

---

## Свързване със Supabase

**1. Създай проект.** На [supabase.com](https://supabase.com) → New project.
Избери регион в ЕС (Frankfurt или Ireland) — данните са на европейци.

**2. Създай таблицата.** В проекта → SQL Editor → New query → постави
съдържанието на [`supabase/schema.sql`](supabase/schema.sql) и го изпълни.

**3. Вземи ключовете.** Project Settings → Data API:

- `Project URL` → отива в `NEXT_PUBLIC_SUPABASE_URL`
- `service_role` ключът → отива в `SUPABASE_SERVICE_ROLE_KEY`

**4. Създай `.env.local`** в папка `web/` по образеца на
[`.env.example`](.env.example) и попълни двете стойности.

> **service_role ключът заобикаля всяко правило за достъп.** Стои само на
> сървъра. Никога не го давай на променлива с префикс `NEXT_PUBLIC_` и
> никога не го качвай в git — `.env.local` вече е в `.gitignore`.

Защитата на редовете е включена, а политики нарочно няма: таблицата е
недостъпна за анонимния ключ и пише единствено сървърът.

## Пускане на живо

```bash
npx vercel --cwd web
```

След първото качване добави двете променливи в Vercel → Project → Settings →
Environment Variables и качи пак. Домейнът се закача от Settings → Domains.

Vercel слага държавата на всяка заявка в заглавката `x-vercel-ip-country`
и страницата я записва сама. Локално тази заглавка липсва и полето остава
празно — това е нормално.

## Какво да гледаш всяка седмица

В Supabase → SQL Editor:

```sql
select
  coalesce(country, 'неизвестна')           as държава,
  count(*)                                  as общо,
  count(*) filter (where plan = 'premium')  as премиум,
  round(100.0 * count(*) filter (where plan = 'premium') / count(*), 1) as процент
from public.waitlist
group by 1
order by общо desc;
```

Числото, което решава съдбата на проекта, е последната колона.

## Устройство

| Файл | Роля |
|---|---|
| `app/page.tsx` | Цялата страница. Текстът се променя тук. |
| `app/layout.tsx` | Шрифтове, заглавие, описание за търсачките. |
| `app/globals.css` | Визуалният език, същият като в мокъпите на приложението. |
| `app/api/waitlist/route.ts` | Приема формата, проверява и записва. |
| `components/Signup.tsx` | Тарифите и формата. Единственият клиентски код. |
| `components/MonthCurve.tsx` | Кривата на месеца. Смята се на сървъра. |
| `lib/waitlist.ts` | Записът в Supabase и проверката на имейл. |

Няма Tailwind и няма библиотека за компоненти — една страница не оправдава
нито едното. Клиентски JavaScript има само във формата.

## Езици

`/bg` и `/en`, статично генерирани. Голият адрес `/` пренасочва към `/bg`.

Текстовете живеят в [`lib/copy.ts`](lib/copy.ts) — двата езика един до друг,
за да се вижда веднага, ако единият изостане. Няма библиотека за преводи:
една страница не я оправдава.

Езикът се записва заедно с имейла. Заявката, която сравнява двата пазара:

```sql
select lang, count(*) as общо,
       count(*) filter (where plan = 'premium') as премиум
from public.waitlist group by lang;
```

Ако англоезичните се записват по-охотно, вниманието трябва да отиде към
DACH и Скандинавия, а не към България.

## Известни ограничения

- **Няма страница за поверителност.** Става задължителна, преди да пуснеш
  реклами или преди приложението да тръгне.
- **Имейлът не се потвърждава.** За списък на чакащи е приемливо; преди
  истинско изпращане на писма мини през доставчик с двойно потвърждение.
- **`hello@invexa.app` в подвала още не съществува.** Смени го с истински
  адрес, преди да пратиш някого на страницата.
